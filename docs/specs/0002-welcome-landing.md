# Spec: หน้าแนะนำโปรเจค (showcase) ที่ `/welcome`

## Problem Statement

ระบบนี้ทำงานครบวงจรแล้ว แต่ไม่มีที่ให้คนอื่นดู — หน้าแรกของเว็บคือหน้าเข้าสู่ระบบด้วย Google ที่คนนอกเปิดมาเจอแต่กำแพง และข้อมูลจริงของผู้เช่าอยู่ในฐานข้อมูลเดียวกับที่ใช้พัฒนา การจะเล่าให้ใครฟังว่าทำอะไรได้จึงต้องถ่ายภาพหน้าจอเองทีละใบ ซึ่งทั้งช้า เสี่ยงข้อมูลผู้เช่าจริงหลุด และเล่าไม่ครบว่างานต้นเดือนจบในครั้งเดียวได้อย่างไร

## Solution

หน้าเว็บสาธารณะหน้าเดียวที่ `/welcome` ซึ่งเปิดได้โดยไม่ต้องล็อกอิน เล่าโปรเจคตามโครง "พิธีกรรมต้นเดือน 5 ขั้น" พร้อม **วิดีโอสาธิตหน้าจอจริง 40–60 วินาที** ที่อัดจากชุดข้อมูลตัวอย่างบนฐานข้อมูลแยก และส่วนท้ายที่บอกว่าระบบสร้างด้วยอะไรพร้อมเหตุผลการตัดสินใจ 4 ข้อ ผู้อ่านคือคนที่มาดูผลงาน เข้าใจได้ในหน้าเดียวว่าโปรเจคนี้แก้ปัญหาอะไร ทำงานอย่างไร และคิดอย่างไร

## User Stories

1. ในฐานะคนที่มาดูผลงาน ฉันต้องการเปิดหน้าแนะนำได้โดยไม่ต้องล็อกอินหรือสร้างบัญชี เพื่อดูว่าระบบนี้ทำอะไรได้ทันทีที่กดลิงก์
2. ในฐานะคนที่มาดูผลงาน ฉันต้องการเข้าใจว่าปัญหาที่ระบบนี้แก้คืออะไรตั้งแต่อยู่ในหน้าจอแรกโดยไม่ต้องเลื่อน เพื่อตัดสินใจว่าจะอ่านต่อ
3. ในฐานะคนที่มาดูผลงาน ฉันต้องการเห็นหลักฐานว่าโปรเจคนี้ใช้งานได้จริงเป็นหน้าจอจริง ไม่ใช่ภาพประกอบที่วาดขึ้น เพื่อเชื่อถือสิ่งที่หน้านี้เล่า
4. ในฐานะคนที่มาดูผลงาน ฉันต้องการดูคลิปเดียวที่พาผ่านงานทั้งรอบบิลตั้งแต่ต้นจนจบ เพื่อเข้าใจทั้งกระบวนการโดยไม่ต้องอ่านย่อหน้าต่าง ๆ
5. ในฐานะคนที่มาดูผลงาน ฉันต้องการกดเล่น หยุด และเลื่อนดูช่วงที่สนใจของคลิปได้เอง เพื่อกลับไปดูจุดที่ไม่ทันโดยไม่ต้องเริ่มใหม่
6. ในฐานะคนที่มาดูผลงาน ฉันต้องการให้คลิปไม่เล่นเองและไม่มีเสียงโดยค่าเริ่มต้น เพื่อไม่ให้การเลื่อนผ่านหน้าถูกรบกวน
7. ในฐานะคนที่มาดูผลงานจากมือถือ ฉันต้องการดูคลิปได้เต็มความกว้างโดยไม่ต้องหมุนจอหรือซูม เพื่อดูรายละเอียดหน้าจอได้จริง
8. ในฐานะคนที่มาดูผลงานจากที่เน็ตช้า ฉันต้องการเห็นภาพนิ่งของคลิปก่อนกดเล่น เพื่อรู้ว่ากำลังจะได้ดูอะไรและไม่ต้องรอไฟล์วิดีโอทั้งก้อน
9. ในฐานะคนที่มาดูผลงาน ฉันต้องการเห็น 5 ขั้นตอนของรอบบิลแบบย่อเป็นข้อความสั้น เพื่อเข้าใจกระบวนการได้แม้ไม่ดูคลิป
10. ในฐานะคนที่มาดูผลงาน ฉันต้องการรู้ว่าระบบรับผิดชอบงานอะไรบ้างนอกจากตัวบิล เพื่อประเมินขอบเขตของโปรเจค
11. ในฐานะคนที่มาดูผลงาน ฉันต้องการรู้ว่าโปรเจคนี้สร้างด้วยเทคโนโลยีอะไร เพื่อประเมินว่าตรงกับงานที่ฉันกำลังหาคนทำหรือไม่
12. ในฐานะคนที่มาดูผลงาน ฉันต้องการเห็นเหตุผลเบื้องหลังการตัดสินใจออกแบบระบบ เพื่อประเมินวิธีคิด ไม่ใช่แค่หน้าตาของหน้าเว็บ
13. ในฐานะคนที่มาดูผลงาน ฉันต้องการกระโดดไปยังหัวข้อที่สนใจจากเมนูด้านบนได้ เพื่อไม่ต้องกวาดตาหาทั้งหน้า
14. ในฐานะคนที่มาดูผลงาน ฉันต้องการเปิดตัวระบบจริงต่อจากหน้าแนะนำได้ทันที เพื่อทดลองเองถ้าสนใจ
15. ในฐานะคนที่มาดูผลงาน ฉันต้องการรู้ชัดว่าข้อมูลที่เห็นในคลิปและภาพทั้งหมดเป็นข้อมูลตัวอย่าง เพื่อไม่เข้าใจผิดว่าเป็นข้อมูลลูกค้าจริงที่ถูกเปิดเผย
16. ในฐานะคนที่มาดูผลงาน ฉันต้องการเห็นชื่อและตัวตนของโปรเจคสม่ำเสมอกับตัวระบบจริง เพื่อมั่นใจว่าเป็นงานชิ้นเดียวกัน
17. ในฐานะคนที่มาดูผลงานบนจอคอมพิวเตอร์ ฉันต้องการตัวอักษรที่อ่านสบายและคอนทราสต์ผ่านเกณฑ์ เพื่อไม่ต้องเพ่งอ่าน
18. ในฐานะคนที่มาดูผลงานบนมือถือ ฉันต้องการหน้าที่ไม่ล้นแนวนอนและไม่ต้องซูมออก เพื่ออ่านจบได้ด้วยการเลื่อนแนวเดียว
19. ในฐานะคนที่ใช้คีย์บอร์ด ฉันต้องการเลื่อนและกดทุกอย่างได้โดยไม่ใช้เมาส์ เพื่ออ่านหน้าให้จบด้วยตนเอง
20. ในฐานะคนที่ใช้โปรแกรมอ่านหน้าจอ ฉันต้องการให้ประกาศภาษาเป็นไทยและมีลำดับหัวข้อที่อ่านรู้เรื่อง เพื่อฟังเนื้อหาตามโครงเดียวกับที่คนอื่นเห็น
21. ในฐานะคนที่ตั้งค่าระบบให้ลดการเคลื่อนไหว ฉันต้องการให้หน้าเว็บไม่ขยับตามการเลื่อน เพื่อไม่ให้เกิดอาการเวียนหัว
22. ในฐานะเจ้าของโปรเจค ฉันต้องการลิงก์เดียวที่ส่งให้ใครก็ได้ดูผลงานชิ้นนี้ เพื่อใช้ในพอร์ตหรือการสมัครงานโดยไม่ต้องอธิบายนำ
23. ในฐานะเจ้าของโปรเจค ฉันต้องการให้ลิงก์นั้นไม่มีคุกกี้หรือข้อมูลบัญชีติดไปด้วย เพื่อให้แชร์ได้อย่างปลอดภัย
24. ในฐานะเจ้าของโปรเจค ฉันต้องการให้เวลาแชร์ลิงก์ในแชทมีตัวอย่างการ์ดที่อ่านออก เพื่อให้คนกดดูจากคำเชิญ
25. ในฐานะเจ้าของโปรเจค ฉันต้องการให้เนื้อหาของหน้านี้อยู่ในที่เดียวและเป็นสำเนาเดียว เพื่อแก้คำผิดได้โดยไม่ต้องไล่หลายที่
26. ในฐานะเจ้าของโปรเจค ฉันต้องการให้การเพิ่มหน้านี้ไม่กระทบหน้าเดิมของแอปเลย เพื่อไม่ให้งานที่ตรวจรับแล้วถดถอย
27. ในฐานะเจ้าของโปรเจค ฉันต้องการความมั่นใจว่าคลิปและภาพทุกชิ้นไม่มีชื่อหรือข้อมูลผู้เช่าจริงติดออกไป เพื่อไม่ให้เกิดปัญหาส่วนตัวกับผู้เช่า
28. ในฐานะเจ้าของโปรเจค ฉันต้องการหน้าที่ไม่อ้างตัวเลขหรือคำรับรองที่ไม่มีจริง เพื่อไม่ให้หน้าแนะนำกลายเป็นคำโฆษณาที่ตรวจสอบไม่ได้
29. ในฐานะเจ้าของโปรเจค ฉันต้องการหน้านี้ที่ไม่มีอะไรต้องดูแลต่อ (ไม่มีระบบหลังบ้านของหน้าเอง ไม่งานตั้งเวลา) เพื่อให้สอดคล้องกับหลัก "เบาและดูแลน้อย"
30. ในฐานะเจ้าของโปรเจค ฉันต้องการส่งงานหน้าแนะนำได้แม้การอัดคลิปจะไม่สำเร็จ เพื่อไม่ให้ทั้งงานค้างเพราะไฟล์เดียว
31. ในฐานะคนที่มาดูผลงานจากมือถือ ฉันต้องการให้ปุ่มทุกปุ่มกดง่ายด้วยนิ้วโป้ง เพื่อไม่ต้องเล็ง
32. ในฐานะคนที่ไม่คุ้นศัพท์เทคนิค ฉันต้องการคำอธิบายที่ตรงไปตรงมาและไม่ยืดยาว เพื่อเข้าใจได้โดยไม่ต้องมีความรู้เบื้องหลัง
33. ในฐานะคนที่มาดูผลงาน ฉันต้องการให้หน้าเว็บขึ้นเร็วและไม่โหลดสคริปต์ก้อนใหญ่ เพื่อไม่ต้องรออ่าน
34. ในฐานะคนที่มาดูผลงานผ่านลิงก์ที่แชร์ต่อ ฉันต้องการให้ลิงก์ตรงไปที่หน้าสาธารณะที่เปิดได้ทุกเบราว์เซอร์ เพื่อไม่เจอหน้ากากที่ต้องเข้าสู่ระบบ

## Implementation Decisions

- **หน้าเว็บเป็น route ฝั่ง worker ไม่ใช่ไฟล์ static** — เพิ่มโมดูลหน้าใหม่ขนานกับหน้า `/register` ที่มีอยู่แล้ว (ตัวเรนเดอร์คืนสตริง HTML จากฟังก์ชันที่ export ออกมาให้เทสเรียกได้ + sub-app ที่ผูก `GET /`) แล้วเมานต์ที่พาธ `/welcome` ใน worker หลัก
  - **เหตุผลที่ต้องเป็น route:** ชุดเทสของโปรเจคใช้ seam เดียวคือขอบเขต HTTP ของ Worker และรันบน `@cloudflare/vitest-pool-workers` ซึ่ง **ไม่เสิร์ฟ static asset** (ทดลองยิง asset ที่มีอยู่จริงในชุดเทสได้ `404`) ไฟล์ static จึงอยู่นอก seam ทั้งหมด ถ้าเลือก static จะไม่มีอะไรกันความผิดพลาดที่หน้าไปอยู่หลังเกตล็อกอิน หรือถูก `not_found_handling: single-page-application` กลบด้วย `index.html`
  - route นี้ **ไม่แตะ `DB` และ `SLIPS` เลย** ไม่มี session ไม่มี middleware ยืนยันตัวตน — หน้าจึงเป็น HTML ล้วนและไม่มีทางรั่วข้อมูลผู้เช่าจากตัวมันเอง
  - เพิ่มพาธของหน้าใหม่ใน `assets.run_worker_first` ของ config worker ไม่อย่างนั้น asset server จะไม่ส่งคำขอไปถึง worker
- **ไม่แตะ SPA เดิมแม้แต่บรรทัดเดียว** — ไม่เพิ่มลิงก์ไป `/welcome` จากในแอป ไม่แก้ `AuthGate` ไม่แก้ `run_worker_first` ของพาธเดิม ไม่แก้ `not_found_handling` หน้าแรก `/` ยังเป็นหน้าเข้าสู่ระบบเหมือนเดิม
- **ไม่ใช้ Tailwind/React/JS ภายนอกในหน้านี้** — HTML เดียว `<html lang="th">` มี `<style>` อยู่ในไฟล์ ใช้ inline SVG แทนฟอนต์ไอคอน และโหลดฟอนต์ชุดเดียวกับแอป (Inter + Noto Sans Thai) จาก Google Fonts สคริปต์เดียวบนหน้าคือสคริปต์เลื่อนเปิดหัวข้อแบบ inline
- **สีและรูปทรงคัดจาก `@theme` ของ `src/client/styles.css` เท่านั้น** ห้ามเดาค่าใหม่: `--ink --charcoal --steel --fog --silver --ash --paper --white --blue --sapphire --mint --green --amber-bg --amber-fg --line` พร้อม radius (input 6 / btn 8 / card 12 / panel 16 / pill 9999) และเงานุ่มสองระดับ มอนอแกรม "วจ" ใช้เส้นโค้งสีเดิมของแอปเป็นกรอบ
- **สื่อทั้งหมดเป็น asset สาธารณะใน `public/`** (คลิปสองฟอร์แมต ภาพตัวอย่าง และภาพ OG) ไม่เก็บใน R2 ไม่ไว้หลัง auth
  - ต้องยืนยันว่า `run_worker_first` ที่ใส่พาธหน้าแบบไม่มี wildcard นั้นจับแบบตรงตัว ไม่กลืนพาธย่อยของสื่อ — ตรวจด้วยการยิงขอไฟล์คลิปแล้วต้องได้ `200` กับ content type ของวิดีโอ ถ้ากลืนจริงให้ย้ายสื่อไปพาธอื่นที่ไม่ใช่พาธย่อยของหน้า
- **ข้อมูลในสื่อต้องมาจากชุดข้อมูลตัวอย่างเท่านั้น** — อัดจากฐานข้อมูล local ที่แยก persist directory จากของเดิม (ของเดิมมีข้อมูลจริงที่คัดมาจาก production) โดย migrate แล้ว seed จากไฟล์ใน `seed/` และลบสภาพแวดล้อมนั้นทิ้งเมื่อจบ
  - แอปเข้าได้ด้วย Google เท่านั้น การอัดจึงต้องสร้าง session แถวเดียวในฐานข้อมูลตัวอย่างแล้วตั้งคุกกี้เซสชันบน `localhost` จากนั้นลบแถวนั้นทิ้งหลังอัดเสร็จ
- **ห้ามกดปุ่มส่ง LINE ทั้งหมดระหว่างอัด** — ค่าตั้งต้นในเครื่องเป็นโทเคนจริงของ LINE OA กดแล้วยิงข้อความออกจริง ใช้หน้าตัวอย่างข้อความ LINE เป็นจุดแสดงการ์ดบิลกับ QR แทน
- **สเปกของคลิป:** viewport 1280×800, ไม่มีแทร็กเสียง, ยาว 40–60 วินาที, ลำดับภาพตามตาราง

  | ช่วง | สิ่งที่ทำให้เห็น |
  |---|---|
  | 0–10s | ขั้นที่ 1 ของหน้ากรอกมิเตอร์ — พิมพ์เลขมิเตอร์ 3 ห้องติดกัน ยอดค่าน้ำ/ค่าไฟ/ยอดรวมขยับสด และแถบความคืบหน้านับเพิ่ม |
  | 10–16s | เลือกทุกห้องที่หัวตาราง แล้วกดตรวจสอบและยืนยัน |
  | 16–24s | ขั้นที่ 2 — เลื่อนดูตารางสรุปและยอดรวม แล้วกดสร้างบิล |
  | 24–32s | ขั้นที่ 3 — หน้าผลการสร้างบิล (ไม่กดส่ง LINE) |
  | 32–42s | หน้าตัวอย่างข้อความ LINE — การ์ดบิลที่ผู้เช่าจะได้รับพร้อม QR พร้อมเพย์ |
  | 42–52s | รายการบิลของเดือน แล้วจบที่แดชบอร์ด |

## Testing Decisions

- **หลักการ:** เทสเฉพาะพฤติกรรมภายนอกที่ผู้ชมหรือระบบภายนอกรับรู้ (ตอบอะไรที่พาธไหน หน้าเว็บมีคุณสมบัติที่ผู้ใช้พึ่งพาจริงไหม) ไม่ผูกกับรายละเอียดภายในของตัวเรนเดอร์ และไม่เทสข้อความบรรยายทุกบรรทัด
- **Seam เดิม seam เดียว ไม่เพิ่ม seam ใหม่:** ขอบเขต HTTP ของ Worker ซึ่งเป็น seam ที่ผู้ใช้ยืนยันไว้แล้วในสเปก 0001 การเลือกทำหน้าเป็น route ฝั่ง worker ทำให้หน้านี้เข้ามาอยู่ใน seam เดิมได้ทันทีโดยไม่ต้องมี harness ใหม่
- **เทสที่จะเขียน:** ไฟล์เทสใหม่หนึ่งไฟล์ที่ยิงคำขอจริงเข้า Worker
  - ได้ `200` และ content type เป็น HTML ที่พาธของหน้า — กันกรณีที่พาธไม่ถูกผูกหรือถูกกลบด้วย fallback
  - คำขอ **ไม่มีคุกกี้เซสชันก็ต้องได้หน้าเต็ม** — กันความผิดพลาดที่หน้าที่ควรสาธารณะเผลอไปอยู่หลังเกตล็อกอิน
  - หน้าไม่ได้พึ่งฐานข้อมูล — เทสยิงผ่านได้โดยไม่ต้อง seed อะไรเลย (สอดคล้องกับการที่ route ไม่แตะ `DB`)
  - ต้องมี marker ของเนื้อหาหลักที่ทำให้แยกออกจากหน้าอื่นได้ (title เฉพาะของหน้า และหัวข้อ hero) — ไม่ใช่การล็อกทั้งหน้า
  - **เทสองค์ประกอบของหน้า (ต่อจาก prior art เดิม):** แยกบล็อก `<style>` ออกมาแล้วตรวจสิ่งที่กระทบผู้ใช้จริง — คู่สีตัวอักษรกับพื้นหลังที่ใช้บนหน้าผ่านคอนทราสต์ระดับ AA, ประกาศ `lang="th"`, องค์ประกอบวิดีโอมี `controls`/`playsinline`/poster, ปุ่มหลักสูงอย่างน้อย 44px และมีการยกเลิกการเคลื่อนไหวใต้ `prefers-reduced-motion`
- **Prior art:** `test/register.test.ts` — ทั้งบล็อก `GET /register` (ยิงพาธหน้าสาธารณะและตรวจ HTML) และบล็อก `GET /register composition` (แกะ `<style>` แล้วคำนวณคอนทราสต์/ขนาดตัวอักษร) เป็นแบบแผนที่ใช้ซ้ำได้ตรง ๆ ตัวช่วยอ่าน CSS จาก HTML กับตัวคำนวณคอนทราสต์ควรถูกดึงออกเป็นโมดูลช่วยของชุดเทสแล้วให้ทั้งสองไฟล์ใช้ร่วมกัน แทนการก๊อปโค้ด
- **เทสตัวเรนเดอร์โดยตรง:** ฟังก์ชันเรนเดอร์หน้าเป็นฟังก์ชันบริสุทธิ์ที่ไม่รับ input จึงเรียกตรงในเทสได้ถ้าต้องการตรวจเชิงลึกโดยไม่ผ่าน HTTP — แต่ค่าเริ่มต้นให้ยิงผ่าน HTTP seam เพื่อรักษาจำนวน seam ให้น้อยที่สุด
- **สิ่งที่ยืนยันอัตโนมัติไม่ได้ ต้องตรวจด้วยมือตอนปิดงาน** (เขียนไว้ให้ชัดเพื่อไม่ให้ถูกมองข้าม):
  - ไฟล์สื่อมีจริงและเข้าถึงได้จากพาธที่หน้าเว็บอ้าง พร้อมขนาดไม่เกินเพดาน และคลิปเล่นได้จริงในเบราว์เซอร์
  - เลย์เอาต์ที่ 1440 / 1024 / 390 — ไม่มีแถบล้นแนวนอน ไม่มีองค์ประกอบค้างจากการเคลื่อนไหว ไม่มีภาพแตก
  - หน้าเดิม `/` ยังเป็นหน้าเข้าสู่ระบบเหมือนเดิม และยังไม่มีลิงก์ใดในแอปชี้ไปหน้าสาธารณะ
  - ตรวจไม่มีข้อมูลจริงหลุด: ชื่อผู้เช่าและเลขห้องทุกชิ้นในคลิปและภาพต้องมาจากชุด seed เท่านั้น (ชุดข้อมูลจริงใช้ชื่อคนละชุดและเลขห้องรูปแบบอื่น) พบของจริงให้อัดใหม่
  - ไม่มี console error บนหน้าสาธารณะที่ทั้งสองขนาดจอ
  - `npm run check` ผ่านเหมือนเดิม (เป็นด่านกันพลาด เพราะงานนี้ไม่แตะซอร์สของแอป)

## Out of Scope

- ลิงก์หรือปุ่มไปหน้าสาธารณะจากในแอป รวมถึงการแก้หน้าเข้าสู่ระบบ
- การแก้ไข ปรับดีไซน์ หรือ refactor ส่วนใดของแอปเดิม
- เสียงบรรยาย คำบรรยายใต้ภาพ (subtitle) หรือเรื่องย่อในคลิป
- หลายภาษา (i18n) และโหมดมืด
- ระบบจัดการเนื้อหาของหน้า (CMS), การวัดผลผู้ชม (analytics), ฟอร์มติดต่อ, การเก็บอีเมลผู้สนใจ
- ราคา แพ็กเกจ จำนวนผู้ใช้ รีวิว คำรับรอง โลโก้ลูกค้า หรือตัวเลขเชิงพาณิชย์ใด ๆ
- การ self-host ฟอนต์เพื่อให้หน้าทำงานออฟไลน์เต็มที่
- การย้ายสื่อไป R2 การทำ signed URL หรือการวางหน้าไว้หลังการยืนยันตัวตน
- การแก้ `not_found_handling` หรือพฤติกรรม asset server ของโปรเจค
- การทำหน้าสาธารณะอื่นเพิ่มเติม (เช่น หน้าเอกสารคู่มือ)

- **slug สำหรับแตกเป็นตั๋วงาน:** `welcome-landing`
- **ชื่อหอ:** หน้าอ้างชื่อ `หอพักวังจันทร์` ตามที่ระบบใช้อยู่ แต่ `PRODUCT.md` ยังระบุว่ายังไม่ยืนยันว่าเป็นชื่อหอจริงหรือชื่อตั้งต้น ถ้าภายหลังเปลี่ยนชื่อ ต้องแก้คำในหน้านี้ทุกจุดที่อ้างถึง
- **ความสอดคล้องกับ ADR:** ADR 0002 เลือกรันทั้งระบบบน Cloudflare Workers — หน้าสาธารณะนี้เป็น route ใน Worker เดียวกันและใช้ asset เดียวกัน จึงไม่เพิ่มแพลตฟอร์มใหม่หรือค่าใช้จ่ายใหม่ ส่วนข้อความใน ADR ที่อ้าง Cloudflare Access เป็นประตูเข้าได้ถูกแทนที่ด้วยการเข้าสู่ระบบด้วย Google แล้วในโค้ดปัจจุบัน
- **สภาพแวดล้อมพัฒนาในเครื่อง:** dev server รันเป็น process ที่ดูแลโดย hub และต้องหยุดก่อนรันชุดเทส เพราะการเข้าถึง D1 พร้อมกันเคยทำให้ workerd ล่ม — งานนี้ไม่แตะซอร์สแอป แต่ต้องหยุดก่อนรันด่านตรวจทุกรอบเช่นเดิม
- **โทนภาษา:** ภาษาไทยทั้งหมด สุภาพ กระชับ ไม่ใช้เครื่องหมายอัศเจรีย์ จำนวนเงินเขียนเป็นตัวเลขตามด้วย " บาท" — หน้าที่เป็น showcase ให้ยึดโทนเดียวกับข้อความในระบบ ไม่ใช่โทนโฆษณา
- **งานที่มาก่อนหน้านี้ที่ยังไม่ถูก commit:** การปรับหน้าสร้างบิลกับตัวเลือก "เลือกทั้งหมด" เสร็จและตรวจแล้วในเซสชันก่อน แต่ยังไม่มีการ commit งานนี้ไม่เกี่ยวข้องและไม่ควรถูกพ่วงไปในการ commit ของหน้าใหม่
