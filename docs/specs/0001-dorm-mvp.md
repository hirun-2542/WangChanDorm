# Spec: ระบบจัดการหอพัก Wang Chan Dorm (MVP)

## Problem Statement

เจ้าของหอพักจัดการห้องพัก ผู้เช่า และบิลค่าเช่ารายเดือนด้วยสมุดจดและแชท LINE ส่วนตัว ทำให้ต้องคำนวณค่าน้ำค่าไฟจากมิเตอร์ด้วยมือทีละห้อง ตามทวงเงินทีละคน และเช็คสลิปการโอนเองว่าจริงไหม ยอดตรงไหม ใช้เวลามากทุกต้นเดือนและมีโอกาสคิดเลขผิด

## Solution

เว็บแอปภาษาไทยสำหรับเจ้าของคนเดียว (ธีม minimal ขาว/น้ำเงิน) รันบน Cloudflare Workers: เก็บข้อมูลห้องพัก/ผู้เช่า, สร้างบิลทั้งหอจากฟอร์มกรอกมิเตอร์หน้าเดียว (รองรับห้องที่ค่าไฟเหมาจ่าย และเพิ่มค่าใช้จ่ายเสริมรายห้อง เช่น wifi ค่าขยะ), ส่งบิลทาง LINE บอทพร้อม QR พร้อมเพย์ยอดตรงกับบิล, รับสลิปคืนทางแชทเดิมแล้วตรวจด้วย EasySlip — ยอดตรงปิดบิลอัตโนมัติพร้อมส่งยืนยันกลับผู้เช่า ยอดไม่ตรงเข้าคิว "รอตรวจ" ให้เจ้าของตัดสิน พร้อมแดชบอร์ดสรุปยอดเงินแยกรายเดือน บิลค้างชำระ และสถานะห้อง บิลแสดงเป็นเอกสาร invoice จริงที่มีมิเตอร์ก่อนหน้าอยู่ด้านซ้าย

## User Stories

1. ในฐานะเจ้าของหอ ฉันต้องการเพิ่มห้องพักพร้อมเลขห้อง ค่าห้องต่อเดือน และเลขมิเตอร์น้ำ/ไฟเริ่มต้น เพื่อเริ่มบันทึกข้อมูลหอไว้ในที่เดียวแทนสมุดจด
2. ในฐานะเจ้าของหอ ฉันต้องการตั้งอัตราค่าน้ำ/ค่าไฟต่อหน่วยเป็นค่าเริ่มต้นของทั้งหอ เพื่อไม่ต้องกรอกซ้ำทุกห้อง
3. ในฐานะเจ้าของหอ ฉันต้องการตั้งอัตราค่าน้ำ/ค่าไฟแบบรายห้องเป็นข้อยกเว้นจากค่าทั้งหอ เพื่อให้ห้องที่ตกลงราคาต่างกันถูกคิดถูกต้อง
4. ในฐานะเจ้าของหอ ฉันต้องการตั้งโหมดค่าไฟของแต่ละห้องเป็น "คิดตามมิเตอร์" หรือ "เหมาจ่ายรายเดือน" เพื่อรองรับห้องที่ตกลงเหมาค่าไฟมาก่อน
5. ในฐานะเจ้าของหอ ฉันต้องการแก้ไขข้อมูลห้องพักได้ตลอดเวลา เพื่อแก้ราคา อัตรา หรือโหมดการคิดเงินที่เปลี่ยน
6. ในฐานะเจ้าของหอ ฉันต้องการเห็นทุกห้องในหน้าเดียวพร้อมสถานะ ว่าง/มีผู้เช่า และโหมดค่าไฟของห้อง เพื่อรู้ทันทีว่ามีห้องว่างให้ปล่อยเช่าหรือไม่
7. ในฐานะเจ้าของหอ ฉันต้องการเพิ่มผู้เช่าด้วยชื่อ เบอร์โทร ห้อง และวันเข้า เพื่อให้ห้องนั้นเปลี่ยนสถานะเป็น "มีผู้เช่า" อัตโนมัติ
8. ในฐานะเจ้าของหอ ฉันต้องการเช็คเอาท์ผู้เช่าโดยระบุวันออก เพื่อให้ห้องกลับเป็น "ว่าง" พร้อมเก็บประวัติผู้เช่าเดิมไว้
9. ในฐานะเจ้าของหอ ฉันต้องการดูรายชื่อผู้เช่าปัจจุบันและผู้ที่ย้ายออกแล้วแยกกันชัดเจน เพื่อหาประวัติย้อนหลังได้เมื่อต้องการ
10. ในฐานะเจ้าของหอ ฉันต้องการแก้ไขข้อมูลผู้เช่า เพื่อแก้เบอร์โทรหรือพิมพ์ชื่อผิด
11. ในฐานะเจ้าของหอ ฉันต้องการเห็นสถานะ "เชื่อม LINE แล้ว/ยังไม่เชื่อม" ของผู้เช่าแต่ละคน เพื่อรู้ว่าใครจะได้รับบิลอัตโนมัติ
12. ในฐานะผู้เช่า ฉันต้องการแอดบอท LINE ของหอแล้วพิมพ์เลขห้องของฉัน เพื่อเชื่อม LINE กับระบบโดยไม่ต้องลงทะเบียนอะไรเพิ่ม
13. ในฐานะผู้เช่า ฉันต้องการให้บอทตอบยืนยันชื่อและห้องกลับมาหลังฉันพิมพ์เลขห้อง เพื่อมั่นใจว่าเชื่อมถูกห้อง
14. ในฐานะผู้เช่า ฉันต้องการให้บอทแจ้งเมื่อเลขห้องที่พิมพ์ไม่ตรงกับห้องที่มีผู้เช่า เพื่อลองใหม่หรือติดต่อเจ้าของ
15. ในฐานะเจ้าของหอ ฉันต้องการเห็นรายชื่อคนที่แอดบอทแต่จับคู่อัตโนมัติไม่ได้ (พิมพ์อย่างอื่น) เพื่อเข้าไปจับคู่กับผู้เช่าเองในหน้าเว็บ
16. ในฐานะเจ้าของหอ ฉันต้องการเชื่อม LINE ตัวเองด้วยการพิมพ์รหัส 6 หลักจากหน้าตั้งค่าให้บอท เพื่อรับการแจ้งเตือนต่างๆ
17. ในฐานะเจ้าของหอ ฉันต้องการออกรหัสเชื่อมเจ้าของใหม่ได้ เพื่อเพิกถอนรหัสเก่าที่รั่วไหล
18. ในฐานะเจ้าของหอ ฉันต้องการสร้างบิลประจำเดือนทั้งหอจากฟอร์มกรอกเลขมิเตอร์หน้าเดียว เพื่อจบงานต้นเดือนในครั้งเดียว
19. ในฐานะเจ้าของหอ ฉันต้องการให้เลขมิเตอร์ครั้งก่อนของแต่ละห้องแสดงขึ้นมาอัตโนมัติในฟอร์ม เพื่อลดการพิมพ์ผิดและไม่ต้องเปิดสมุดเทียบ
20. ในฐานะเจ้าของหอ ฉันต้องการเห็นยอดค่าน้ำ ค่าไฟ และยอดรวมคิดสดระหว่างกรอกมิเตอร์ เพื่อสังเกตเลขผิดปกติทันที
21. ในฐานะเจ้าของหอ ฉันต้องการให้ระบบเตือนเมื่อเลขมิเตอร์ที่กรอกน้อยกว่าครั้งก่อน เพื่อกันบิลติดลบหรือหน่วยเพี้ยน
22. ในฐานะเจ้าของหอ ฉันต้องการกรอกเฉพาะยอดค่าไฟเต็มสำหรับห้องที่เหมาจ่าย (ระบบยังบันทึกเลขมิเตอร์ให้เหมือนเดิม) เพื่อไม่ต้องคิดอัตราต่อหน่วยกับห้องที่ตกลงเหมามา
23. ในฐานะเจ้าของหอ ฉันต้องการเพิ่มค่าใช้จ่ายเพิ่มเติมรายห้องตอนสร้างบิล เช่น ค่าอินเทอร์เน็ต ค่าจัดการขยะ เพื่อให้บิลครบทุกค่าที่เก็บจริง
24. ในฐานะเจ้าของหอ ฉันต้องการให้บิลใช้อัตราและราคา ณ วันที่สร้างบิล เพื่อให้การแก้ค่าตั้งต้นภายหลังไม่กระทบบิลเก่า
25. ในฐานะเจ้าของหอ ฉันต้องการแก้ไขหรือลบบิลที่ยังไม่ได้รับชำระ รวมถึงแก้ค่าใช้จ่ายเพิ่มเติม เพื่อแก้ไขความผิดพลาดก่อนส่งหรือก่อนปิดบิล
26. ในฐานะเจ้าของหอ ฉันต้องการดูลิสต์บิลของแต่ละเดือนพร้อมสถานะ จ่ายแล้ว/ยังไม่จ่าย เพื่อตามเก็บเงินได้ง่าย
27. ในฐานะเจ้าของหอ ฉันต้องการดูบิลเป็นเอกสาร invoice ที่มีเลขมิเตอร์ก่อนหน้า→ปัจจุบันอยู่ด้านซ้ายและตารางรายการค่าใช้จ่ายด้านขวา เพื่ออ่านบิลแบบเดียวกับใบแจ้งหนี้กระดาษที่คุ้นเคย
28. ในฐานะเจ้าของหอ ฉันต้องการส่งบิลทั้งหอทาง LINE ในคลิกเดียวหลังตรวจทานยอด เพื่อไม่ต้องส่งทีละคน
29. ในฐานะเจ้าของหอ ฉันต้องการเห็นรายชื่อผู้เช่าที่ส่งบิลไม่ได้เพราะยังไม่เชื่อม LINE เพื่อตามงานด้วยตัวเอง
30. ในฐานะเจ้าของหอ ฉันต้องการส่งบิลซ้ำรายห้องทาง LINE เพื่อแจ้งซ้ำแก่ผู้ที่ยังไม่จ่าย
31. ในฐานะเจ้าของหอ ฉันต้องการได้รับสรุปทาง LINE หลังสร้าง/ส่งบิลทั้งหอ (จำนวนบิล ยอดรวม ส่งสำเร็จกี่คน) เพื่อรู้ยอดที่ควรเก็บเดือนนั้นโดยไม่ต้องเปิดเว็บ
32. ในฐานะผู้เช่า ฉันต้องการได้รับบิลใน LINE ที่ระบุค่าห้อง ค่าน้ำ ค่าไฟ ค่าใช้จ่ายเพิ่มเติม จำนวนหน่วย และยอดรวมชัดเจน เพื่อรู้ว่าต้องจ่ายเท่าไหร่และมาจากอะไร
33. ในฐานะผู้เช่า ฉันต้องการได้รับ QR พร้อมเพย์ที่ตั้งยอดตรงกับบิลในข้อความเดียวกัน เพื่อสแกนจ่ายได้ทันทีโดยไม่พิมพ์ยอดเอง
34. ในฐานะผู้เช่า ฉันต้องการส่งรูปสลิปการโอนกลับมาในแชทบอทเดิม เพื่อแจ้งหลักฐานการจ่ายโดยไม่ต้องไปช่องทางอื่น
35. ในฐานะผู้เช่า ฉันต้องการได้รับข้อความยืนยันยอดและเดือนทันทีที่บิลของฉันถูกปิด เพื่อมั่นใจว่าเจ้าของรับเงินแล้วและไม่ถูกทวนซ้ำ
36. ในฐานะเจ้าของหอ ฉันต้องการให้ระบบตรวจสลิปด้วย EasySlip และปิดบิลอัตโนมัติเมื่อสลิปจริงและยอดตรงบิลล่าสุดที่ยังไม่จ่ายของห้องนั้น เพื่อไม่ต้องเช็คสลิปทีละใบ
37. ในฐานะเจ้าของหอ ฉันต้องการให้สลิปที่ยอดไม่ตรงหรือตรวจไม่ผ่านเข้าคิว "รอตรวจ" และแจ้งเตือน LINE เจ้าของพร้อมรูป เพื่อใช้ดุลพินิจของคนเฉพาะกรณีที่จำเป็น
38. ในฐานะเจ้าของหอ ฉันต้องการเห็นรูปสลิป ยอดในสลิปเทียบยอดบิล และผลการตรวจ EasySlip ในคิวรอตรวจ เพื่อตัดสินใจบนข้อมูลครบถ้วน
39. ในฐานะเจ้าของหอ ฉันต้องการปิดบิลเองด้วยมือโดยระบุช่องทาง (โอน/เงินสด) เพื่อรองรับการจ่ายเงินสดหรือสลิปที่ส่งมาทางอื่น
40. ในฐานะเจ้าของหอ ฉันต้องการปิดบิลจากสลิปที่ยอดไม่ตรงในคิวรอตรวจได้ เพื่อกรณียอมรับการจ่ายบางส่วน/ยอดพิเศษ
41. ในฐานะเจ้าของหอ ฉันต้องการปฏิเสธสลิปที่ไม่ใช่ของบิลใด เพื่อให้สลิปผิดใบไม่ไปปิดบิลผิด
42. ในฐานะเจ้าของหอ ฉันต้องการเลือกดูข้อมูลของแต่ละเดือนบนแดชบอร์ดได้ เพื่อเทียบภาพรวมย้อนหลังแทนที่จะเห็นเฉพาะเดือนปัจจุบัน
43. ในฐานะเจ้าของหอ ฉันต้องการดูแดชบอร์ดสรุปยอดควรเก็บ ยอดที่เก็บได้ ค้างชำระ และห้องว่างของเดือนที่เลือก เพื่อเห็นภาพรวมการเงินในพริบตา
44. ในฐานะเจ้าของหอ ฉันต้องการดูกราฟรายรับรายเดือนย้อนหลัง เพื่อเห็นแนวโน้มรายได้ของหอ
45. ในฐานะเจ้าของหอ ฉันต้องการดูลิสต์บิลค้างชำระเรียงตามอายุบิล เพื่อรู้ว่าควรทวนใครก่อน
46. ในฐานะเจ้าของหอ ฉันต้องการดูกริดภาพรวมห้องที่แสดงทั้งสถานะห้องและสถานะบิลของเดือนที่เลือก เพื่อกวาดตาครบทั้งหอในหน้าเดียว
47. ในฐานะเจ้าของหอ ฉันต้องการตั้งค่าเบอร์พร้อมเพย์/เลขนิติบุคคลและชื่อบัญชี เพื่อให้ QR และบิลอ้างอิงบัญชีรับเงินที่ถูกต้อง
48. ในฐานะเจ้าของหอ ฉันต้องการตั้งชื่อหอและชื่อเจ้าของ เพื่อให้ข้อความ LINE และ invoice แสดงตัวตนถูกต้อง
49. ในฐานะเจ้าของหอ ฉันต้องการเข้าใช้เว็บได้เฉพาะตัวเองผ่านการล็อกอินแบบ SSO (Cloudflare Access) เพื่อให้ข้อมูลการเงินของหอไม่รั่วไหล
50. ในฐานะเจ้าของหอ ฉันต้องการใช้ระบบจากมือถือและคอมพิวเตอร์ได้ (responsive) เพื่อทำงานได้ทุกที่
51. ในฐานะเจ้าของหอ ฉันต้องการเห็นข้อความแนะนำในหน้าเว็บเมื่อผู้เช่ายังไม่เชื่อม LINE (ให้บอกผู้เช่าแอดบอทและพิมพ์เลขห้อง) เพื่อรู้วิธีแก้ปัญหาหน้างาน

## Implementation Decisions

- **แพลตฟอร์ม:** Cloudflare Workers (TypeScript + Hono) เสิร์ฟ React SPA (Vite) เป็น static assets, D1 เป็นฐานข้อมูล, R2 เก็บภาพสลิป — ไม่มี cron ทุกอย่างเป็น event-driven
- **การยืนยันตัวตน:** Cloudflare Access ครอบทั้งแอป ยกเว้น path สาธารณะ 3 จุด: webhook ของ LINE, route รูป QR, route รูปสลิป (ให้ EasySlip ดึงได้)
- **โดเมน (จาก glossary ของโปรเจกต์):** ห้องพัก, ผู้เช่า, บิล, การอ่านมิเตอร์, ปิดบิล, สลิป, คิวรอตรวจ, การเชื่อม LINE, เจ้าของ

  - `rooms(room_number UNIQUE, rent, water_rate NULL, electric_mode: meter|flat, electric_rate NULL, water_meter_init, electric_meter_init, status)` — อัตรา NULL = ใช้ค่าทั้งหอ; `electric_mode = flat` = ค่าไฟเหมาจ่าย (rate ไม่ใช้)
  - `tenants(room_id, check_in_date, check_out_date NULL, line_user_id NULL UNIQUE, status)` — line_user_id ผูกกับคน ไม่ใช่ห้อง
  - `bills(room_id, period YYYY-MM ค.ศ. UNIQUE(room_id, period), rent, water_prev/curr/rate/units/amount, electric_mode, electric_prev/curr/rate NULL/units NULL/amount, total, status, paid_at, paid_method, sent_at)` — snapshot ทุกค่า ณ วันสร้าง; `period` เป็น ค.ศ. รูปแบบ `YYYY-MM` (client แสดง พ.ศ. เช่น `2026-09` = กันยายน 2569); `electric_mode` เป็น snapshot อีกคอลัมน์ เพื่อให้เคสเหมาจ่ายชัดเจนจากตัวมันเอง ไม่ต้องอนุมานจาก rate/units ที่เป็น NULL; ห้องเหมา: บันทึก prev/curr มิเตอร์ไฟด้วย แต่ rate/units เป็น NULL และ amount = ยอดเต็มที่กรอก
  - `bill_charges(id, bill_id, name, amount, position)` — ค่าใช้จ่ายเพิ่มเติมต่อบิล เช่น ค่าอินเทอร์เน็ต ค่าจัดการขยะ
  - `slips(bill_id NULL, line_user_id, image_key, easyslip_result, amount NULL, status)` — สลิปหนึ่งใบปิดได้บิลเดียว
  - `settings(key, value)` — อัตรา default, promptpay_id, owner_line_user_id, ชื่อหอ, รหัสเชื่อมเจ้าของ
  - `line_pending(line_user_id PK, display_name NULL, last_message, last_seen_at)` — คิว "รอเชื่อม" ของคนที่แอดบอทแล้วจับคู่อัตโนมัติไม่ได้ (เก็บข้อความล่าสุดที่พิมพ์); แถวถูกลบทันทีที่ผู้ใช้รายนั้นเชื่อมกับผู้เช่าสำเร็จ ไม่ว่าจะเชื่อมเองผ่านการพิมพ์เลขห้องหรือเจ้าของจับคู่ให้ในหน้าเว็บ
  - `bills.total = rent + water_amount + electric_amount + ผลรวม bill_charges` เสมอ
- **กฎโดเมนสำคัญ:**
  - 1 บิล/ห้อง/เดือน; สร้างบิลเฉพาะห้องที่มีผู้เช่า
  - หน่วยน้ำ = มิเตอร์ปัจจุบัน − ครั้งก่อน (บิลแรกใช้เลขเริ่มต้นของห้อง); ห้ามค่าติดลบ — ปฏิเสธการสร้างบิลห้องนั้นพร้อมข้อความเตือน (ใช้กับทั้งห้องมิเตอร์และห้องเหมา เพราะมิเตอร์ยังบันทึกทุกกรณี)
  - ห้องเหมาจ่ายค่าไฟ: กรอกยอดค่าไฟเต็มตอนสร้างบิล (≥ 0) ระบบไม่คิดหน่วย
  - ค่าใช้จ่ายเพิ่มเติม: เพิ่ม/แก้/ลบได้ต่อบิล ก่อนปิดบิล
  - แก้ไข/ลบบิลได้เฉพาะสถานะยังไม่จ่าย
  - เช็คเอาท์ = บันทึกวันออก + ห้องกลับเป็นว่าง; ผู้เช่าย้ายห้องไม่ได้ใน MVP (ต้องออกก่อนเข้าใหม่)
  - การเชื่อม LINE: ผู้เช่าพิมพ์เลขห้องให้บอท → ผูก line_user_id กับผู้เช่าปัจจุบันของห้องนั้น + บอทยืนยันชื่อกลับ; ข้อความอื่น → เก็บเป็น "รอเชื่อม" ให้เจ้าของจับคู่ในหน้าผู้เช่า; รหัส 6 หลัก → เชื่อมเป็นเจ้าของ
  - การปิดบิลอัตโนมัติ: สลิปต้องผ่าน EasySlip (สถานะ success) และยอดตรงกับยอดรวมทั้งสิ้น (รวมค่าใช้จ่ายเพิ่มเติมแล้ว) ของบิล unpaid ล่าสุดของห้องผู้ส่งเท่านั้น; ไม่ตรง → คิวรอตรวจ; สลิปใบหนึ่งใช้ปิดบิลได้ไม่เกินหนึ่งใบ
- **API contract (REST, อยู่หลัง Access):**
  - `rooms` CRUD (รวม electric_mode); `tenants` CRUD; `GET/PUT /settings` + ออกรหัสเจ้าของใหม่; `GET /api/line/pending` และ `POST /api/line/pending/:lineUserId/link` สำหรับจับคู่ pending LINE
  - `POST /bills/generate {period, มิเตอร์รายห้อง, ยอดไฟเหมารายห้อง, ค่าใช้จ่ายเพิ่มเติมรายห้อง}` — เซิร์ฟเวอร์คิดยอดเงินเองทั้งหมด (อัตราที่ใช้จริง = override ของห้อง ?? ค่า default); `GET /bills?period`; `GET /bills/meter-sheet?period` (ห้องที่มีผู้เช่าทุกห้อง + เลขมิเตอร์ครั้งก่อน + อัตราที่ใช้จริง + `existingBillId` ของเดือนนั้น); `PATCH/DELETE /bills/:id` (unpaid เท่านั้น, แก้ extras ได้); `POST /bills/:id/send`; `POST /bills/send-all`; `POST /bills/:id/mark-paid {method}`
  - `GET /review-queue`; `POST /slips/:id/resolve {settle|reject}`
  - `GET /stats/dashboard?period` — KPI + ค้างชำระ + กริดห้อง + กราฟ ตามเดือนที่เลือก
  - Public: `POST /webhook/line` (ตรวจ X-Line-Signature แบบ HMAC-SHA256 timing-safe), `GET /qr/:billId.png`, `GET /slips/:imageKey.png` (imageKey สุ่ม 128-bit ไม่เดาได้)
- **หน้ารายละเอียดบิล (invoice):** แสดงเป็นเอกสาร invoice — แถวหัว (ชื่อหอ/เจ้าของ/พร้อมเพย์ + เลขที่บิล/วันที่ออก), บล็อกมิเตอร์ก่อนหน้า→ปัจจุบัน อยู่แผงซ้าย, ตารางรายการค่าใช้จ่าย (ค่าห้อง/น้ำ/ไฟ/ค่าใช้จ่ายเพิ่ม) อยู่ด้านขวา, ยอดรวมมีเส้นคู่, QR + ช่องทางชำระท้ายเอกสาร
- **LINE Messaging API:** push บิลเป็น Flex message (แยกยอดครบรวมค่าใช้จ่ายเพิ่ม + รูป QR + ชี้นำส่งสลิปกลับ), reply สำหรับตอบ webhook, push ยืนยันการชำระ, push แจ้งเจ้าของ (สลิปรอตรวจ + สรุปหลังส่งบิลทั้งหอ)
- **QR พร้อมเพย์:** สร้าง payload EMVCo (พร้อมเพย์ + ยอดรวมทั้งสิ้นของบิล) และเรนเดอร์เป็น PNG เองใน Worker เสิร์ฟจาก route สาธารณะ
- **EasySlip:** ส่ง URL รูปสลิป (จาก R2 ผ่าน route สาธารณะ) ให้ API ตรวจ; เก็บผลลัพธ์ดิบลง `slips.easyslip_result`
- **Secrets:** `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `EASYSLIP_API_KEY` — ผ่าน wrangler secrets ไม่เก็บใน source; รหัสเชื่อมเจ้าของเก็บในตาราง `settings` และแสดงในหน้าตั้งค่า (ไม่ใช่ wrangler secret)
- **UX:** ตาม prototype ที่ตกลงไว้ที่ `design/index.html` — minimal ขาว/น้ำเงิน, ฟอนต์ IBM Plex Sans Thai, 7 หน้า (แดชบอร์ดมี filter รายเดือน, ห้องพัก, ผู้เช่า, บิล, รอตรวจ, ข้อความ LINE, ตั้งค่า)

## Testing Decisions

- **หลักการ:** เทสเฉพาะพฤติกรรมภายนอกที่ผู้ใช้/ระบบภายนอกรับรู้ (HTTP response, ข้อความที่ push ออกไป, สถานะที่อ่านกลับได้จาก API) ไม่เทส implementation ภายใน
- **Seam เดียว (ที่ผู้ใช้ยืนยันแล้ว):** ขอบเขต HTTP ของ Worker ทั้งแอป — เทสยิง HTTP จริงเข้า REST API และจำลอง webhook ของ LINE, รันบน D1/R2 จริงผ่าน `@cloudflare/vitest-pool-workers`, และ mock `fetch` ขาออก (LINE Messaging API, EasySlip) พร้อม assert เนื้อหาที่ระบบส่งออกไป
- **Webhook:** เทสสร้าง payload พร้อม signature จริง (HMAC ด้วย test secret) และกรณี signature ผิดต้องถูกปฏิเสธ
- **สถานการณ์หลักที่ต้องครบ:** เพิ่มห้อง→ผู้เช่า→เชื่อม LINE→สร้างบิล (ทั้งห้องมิเตอร์/ห้องเหมา/มี extras)→ส่งบิล→ส่งสลิปยอดตรง (ปิดอัตโนมัติ+ยืนยันกลับ) / ยอดไม่ตรง (คิวรอตรวจ+แจ้งเจ้าของ) / ตรวจไม่ผ่าน; มิเตอร์ย้อนหลัง; แก้/ลบบิล unpaid รวม extras; เช็คเอาท์แล้วห้องว่าง; dashboard ตามเดือนที่เลือก
- **ฟังก์ชันล้วน:** การคำนวณหน่วย/ยอดบิล (รวมโหมดเหมาและ extras) และ payload EMVCo + CRC16 เทสด้วย unit test ที่ known test vector (ไม่มี I/O)
- **Prior art:** โปรเจกต์ใหม่ ยังไม่มีเทสเดิม — ชุดนี้จะเป็นแบบแผนให้เทสถัดไป (ไฟล์เทสวางขนานกับ source, ใช้ vitest)

## Out of Scope

- ค่ามัดจำ/เงินคืน, กำหนดชำระ (due date), ค่าปรับ, การทวงหนี้อัตโนมัติ/แจ้งบิลเกินกำหนด
- งานตั้งเวลา (cron) ใดๆ รวมถึงการสร้างบิลอัตโนมัติรายเดือน
- มุมมองผู้เช่า (tenant portal) — ผู้เช่าใช้เฉพาะผ่านบอท LINE
- ผู้ใช้หลายคน/สิทธิ์หลายระดับ, การย้ายห้องของผู้เช่า, บิลส่วนเดือน, การจ่ายแบบผ่อน
- การรับสลิปจากช่องทางอื่นที่ไม่ใช่แชทบอท (อัปโหลดเองในเว็บ, อีเมล)
- รายงาน/ส่งออกข้อมูล, ใบเสร็จพิมพ์, การแจ้งเตือนผู้เช่าใหม่ที่แอดบอท, การอ่านมิเตอร์อัตโนมัติ
- เทมเพลต/ค่าใช้จ่ายเพิ่มเติมแบบตั้งค่าล่วงหน้าให้เติมอัตโนมัติทุกเดือน (MVP ให้เพิ่มด้วยมือตอนสร้างบิล), โหมดเหมาจ่ายค่าน้ำ (สถาปัตยกรรมรองรับ แต่ UI ยังไม่ทำ)
